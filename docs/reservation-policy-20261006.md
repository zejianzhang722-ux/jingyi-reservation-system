# 预约规则更新

- 按**预约所选日期、同一种功能房**最多3次。取消和拒绝释放次数；待审核、已通过、使用中、已完成、爽约保留次数。加入组团也计入，发起人不重复计数。
- 不同功能房、个人及参与组团均不能时间重叠，相邻时段允许。修改预约同样校验所有成员。
- 共享空间、舞蹈室、多功能厅至少2人组团，一个时段仅一个团队。舞蹈室无团队预约时个人可直接进入，有团队时个人不可进入；管理人员收到占用和解除提醒。
- 创新工作坊、备赛间按**声明的实际参与人数（包含发起人）**预留容量；允许多个个人或团队同时预约。系统成员登记不缩减预留人数。
- D128党团活动室仅联系辅导员，不通过系统申请。
- 待审核、待辅导员审核、已通过均可取消；使用中、已完成、爽约不可取消。团队由发起人取消；重复取消不重复通知或释放。
- 开始前10分钟提醒；开始前15分钟至开始后15分钟可签到；超过开始后15分钟未签到视为爽约，只扣分一次。
- 信用0—120分，仅影响新预约、加入组团及修改预约，不限制登录。≥80分可提前3天、同类房每天3次；60–79分提前2天、每天2次；30–59分提前1天、每天1次、08:00–20:00；0–29分仅当天、每天1次、09:00–17:00。既有预约仍可查看、取消及签到签退；手动停用账号另按账号管理权限处理。

## 部署与验证

当前本机使用模拟数据库。真实MySQL升级时，先备份，再执行 `server/sql/migrations/20261006_room_booking_policy.sql` 和 `node scripts/apply-admin-notification-migration.js`。新建数据库的schema已包含管理员独立通知表和新房间状态。

`npm run check:reservation-policy` 执行规则、签到、提醒、信用、消息分类专项测试。另执行取消、修改预约、舞蹈管理提醒和前端房间规则检查；真实MySQL并发仍需测试数据库验证。

根目录一键启动保留手动启动方式，不创建开机触发任务；隐藏后台已开启预约定时任务。站内提醒已可用，微信订阅消息受平台模板配置和用户授权约束，不能保证未经授权也能推送。
