## 更新范围

本轮包含角色与扫码隔离、两端管理员页面、信用预约权限、房间预约规则、组团容量与冲突、提醒及管理员通知，以及长期/定时空间状态。参考[更新记录](../CHANGELOG.md)、[使用手册](user-guide.md)和[检查报告](qa/20261007-room-status-recent-cross-client-audit.md)。

## 现有MySQL数据库

先备份，确认当前数据库名称和环境，在专用测试数据库验证后再升级正式环境。不要重新执行seed.sql覆盖已有业务数据。

1. 检查先前预约、组团、通知、审计等迁移是否已经完成。
2. 执行server/sql/migrations/20261006_room_booking_policy.sql，补齐辅导员预约状态与共享容量槽位规则。
3. 执行server/sql/migrations/20261006_admin_notifications.sql，或运行node scripts/apply-admin-notification-migration.js，创建管理员独立通知表。
4. 检查rooms是否已有status_schedules字段；未存在时执行server/sql/migrations/20261007_room_status_schedules.sql。该ADD COLUMN只能执行一次，重复执行会提示字段已存在。
5. 重启API与Scheduler Worker，按部署配置保持定时任务运行，再检查/api/v1/ops/ready。

新建数据库使用当前schema.sql，其中已包含新字段和管理员通知表；是否加载演示seed.sql由环境用途决定。

本机验证使用非生产模拟数据，尚未验证真实数据库迁移和生产并发。不要将本地通过结果解释为真实数据库已升级。

## 信用与状态兼容

信用分不因低分写入封禁状态，旧有期限信用限制在登录时清理；不会修改信用余额和日志。手动账号停用仍生效。旧banThreshold等字段保留兼容，表示预约严格限制区间；旧限制天数不再参与信用处罚。

房间status仍是长期状态，status_schedules保存定时安排；当前有效状态及预约可用性在读取时计算。定时安排结束后使用最新长期状态，不依赖过期任务把旧状态写回。已有预约不自动取消。D128仍不接受系统预约。

```bash
npm run check:comprehensive
node scripts/room-status-schedule-check.js
node scripts/run-isolated-check.js scripts/room-status-schedule-api-check.js
cd admin
npm run build

```

完整检查使用临时数据和独立端口。需要真实MySQL/Redis或微信开发者工具的检查会明确列为未验证，不能把跳过当作通过。

实际小程序检查需已登录的微信开发者工具自动化会话，端口9420，并安装miniprogram-automator。可以把依赖安装在本地目录，使用MINIPROGRAM_AUTOMATOR_PATH指定模块目录，或NODE_PATH指定依赖目录，运行scripts/admin-experience-runtime.cjs、room-entry-runtime-check.cjs、timeline-layout-runtime-check.cjs。宿管手册截图工具额外需要pngjs，可通过PNGJS_PATH或NODE_PATH指定。日志、依赖缓存、临时动态凭证及运行中测试数据不上传GitHub。
