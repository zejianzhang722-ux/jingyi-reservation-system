# 身份验证与会话安全修复设计

## 范围

本次只修复三个已确认问题：模拟微信登录可冒充学生、过期访问令牌可被用于刷新会话、账号停用或降权后旧令牌仍保留权限。不修改预约业务、管理界面和数据库结构。

## 设计

1. 模拟微信登录仅在明确的测试环境开关启用。其他环境收到 `mock_code_` 时直接拒绝，不再进入用户匹配流程。
2. 刷新会话必须提交有效的刷新令牌。服务端验证令牌类型、Redis 中保存的当前令牌、账号当前状态与角色；缺失、过期、不匹配或会话存储不可用时均拒绝刷新。
3. 管理端受保护请求在令牌校验后查询管理员当前状态与角色，禁用账号立即失效，角色调整立即生效。学生请求至少核对账号是否仍可用。
4. 删除刷新接口中不可到达的旧实现，避免未来误用。

## 兼容性

现有正常登录和携带刷新令牌的客户端流程保持不变。依赖“仅凭过期访问令牌刷新”的旧行为将被拒绝，这是预期的安全收紧。测试环境需要显式开启模拟登录。

## 验证

新增自动测试覆盖：生产环境拒绝模拟登录、缺少刷新令牌时拒绝、访问令牌不能充当刷新令牌、Redis 会话不匹配或不可用时拒绝、禁用账号和角色变更即时生效。随后运行服务端完整集成测试，并检查改动范围。
