# 管理后台空间监控、账号管理与导航重构设计

## 目标

修复空间监控时间线详情空白问题，纠正账号管理页面的数据混合与范围显示问题，并按导生管理员、辅导员、超级管理员的真实工作职责重构左侧导航和后台文案。

## 使用对象与原则

- 导生管理员：处理普通预约、签到核销、使用记录、违规记录和空间运行查看；数据范围可为全院或指定楼栋。
- 辅导员：全院范围，继承导生管理员的日常运营能力，并重点处理特殊功能房、团队预约、海报等高级审核。
- 超级管理员：全院范围，拥有全部运营、配置、账号和系统管理能力。
- 角色决定可执行的功能，数据范围决定可查看和处理的数据，两者不得混用。

## 空间监控时间线

### 根因方向

现有详情使用图表热力格展示单行状态。接口已经返回时间段，但图表只显示坐标轴而不稳定显示状态格，导致管理员看到一片空白。界面同时没有清楚区分“全天空闲”“没有数据”和“加载失败”。

### 新交互

- 使用页面原生时间格替代单行热力图，按半小时显示从开放到关闭的完整时间轴。
- 顶部展示日期、开放时间、当前状态和今日预约数量。
- 状态分为：空闲、已预约、使用中、维护，并提供固定图例。
- 普通功能房的占用时段显示预约人、时间范围和用途；自习室显示剩余座位和总座位。
- 全天无预约时明确显示“今日暂无预约，当前时段均可使用”。
- 加载失败时保留房间基础信息，并显示“时间线暂时未能加载”和重试按钮。
- 弹窗打开、切换房间和窗口尺寸变化后，时间格均保持完整可读。

## 账号管理

### 数据与页面分离

- “宿生账号”和“管理账号”使用独立页签与独立查询条件。
- 管理账号页只显示导生管理员、辅导员和超级管理员，不混入宿生。
- 宿生页只显示宿生。
- 切换页签时重置角色筛选和页码，避免沿用另一类账号的条件。

### 列表信息

- 不向管理员展示 `admin-1`、`student-1` 等内部编号。
- 管理账号显示：账号、姓名、身份、管理范围、状态、最近登录、创建时间、操作。
- 宿生账号显示：学号、姓名、楼栋、信用状态、账号状态、创建时间、操作。
- 数据范围显示真实楼栋名称，例如“B 座”，不得显示“楼栋 1”或裸数字。
- 全院范围统一显示“全院”。

### 新增与编辑

- 辅导员和超级管理员固定为全院范围，范围控件只读并说明原因。
- 导生管理员必须选择“全院”或一个具体楼栋。
- 超级管理员不能停用自己的当前账号。
- 停用账号、修改身份、修改数据范围需要明确确认，说明会影响的使用权限。
- 批量导入管理账号时必须支持数据范围；缺少范围的导生管理员记录不得静默创建。

## 导航结构

采用“角色工作区 + 折叠分组”方案。侧栏顶部显示当前工作区身份，各分组支持折叠并记住当前账号的展开状态。

### 分组

1. 今日工作：工作台、待我审批。
2. 预约与使用：普通预约、重点预约、签到核销、全部预约、阅览室记录。
3. 空间运行：空间监控。
4. 书院治理：违规记录、黑名单、意见反馈。
5. 数据与报表：数据概览、导出报表。
6. 内容审核：海报审核。
7. 系统管理（仅超级管理员）：功能房、楼栋与座位、开放规则、账号管理、公告、海报位置、操作记录与数据备份。

### 各角色默认重点

- 导生管理员：普通预约、签到核销和空间监控。
- 辅导员：重点预约置顶，并突出海报审核与高级治理待办；同时保留普通预约入口。
- 超级管理员：展示全部待办及系统管理入口。
- 无权访问的条目不显示，后端接口仍独立校验，不能只依赖菜单隐藏。

## 面向管理员的文案

- 不展示 WebSocket、Token、API、数据表、Mock、缓存、角色裁剪等开发术语。
- “WebSocket 已连接”改为“实时更新正常”；断开时改为“实时更新暂时中断，可手动刷新”。
- 登录凭证问题统一说明为“登录状态已失效，请重新登录”。
- “写入不同数据表”改为“分别管理宿生与工作人员账号”。
- “按角色裁剪”改为“已按当前身份显示可用功能”。
- 加载失败提示必须说明受影响的内容，并提供重试或手动刷新方式。
- 操作日志在面向用户的菜单中称为“操作记录”；技术日志内容不直接暴露给普通管理员。

## 状态与异常处理

- 时间线、账号列表和导航待办分别维护加载、成功、空结果、失败状态。
- 页面刷新失败时不清空上一次成功数据，并在对应区域显示重试入口。
- 账号查询必须由后端按账号类型过滤，前端页签过滤不能作为唯一保障。
- 实时更新中断不阻止管理员查看已有数据和手动刷新。

## 验证标准

- 任意有时间线数据的房间详情都能显示连续状态格；全天空闲和加载失败有不同提示。
- 管理账号页不出现宿生，宿生页不出现管理账号；楼栋名称和全院范围显示正确。
- 超级管理员无法停用当前登录账号。
- 三类账号分别只显示符合职责的导航项，折叠状态能在刷新后恢复。
- 辅导员能同时进入普通审批和重点审批，重点审批在导航中更醒目。
- 页面上不再出现面向开发者的连接、认证、存储与接口术语。
- 后台构建、权限验证、账号管理验证、时间线验证和浏览器实际操作检查全部通过。
