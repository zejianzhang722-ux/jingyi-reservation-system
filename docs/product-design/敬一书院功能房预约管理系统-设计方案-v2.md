## 一、项目背景与现有问题分析

### 1.1 现状

敬一书院（BCD座 + 二期1幢）目前通过「草料二维码」第三方平台实现功能房预约管理。宿生扫描各功能房门上的二维码进入草料二维码小程序，填写表单提交预约，导生会后台审核。部分功能房（影音室、多功能厅、研讨室等）还需额外打印申请表交辅导员签字或宿管阿姨确认。

### 1.2 现有痛点

| 问题 | 说明 |
|------|------|
| **依赖第三方平台** | 草料二维码非自主可控，数据安全存在隐患 |
| **体验割裂** | 多种预约方式并存（线上扫码/打印签字/共享文档），流程不统一 |
| **缺乏可视化管理** | 无统一后台看板，审核效率低，无法实时查看占用状态 |
| **时间粒度粗糙** | 仅支持固定时段，无法灵活选择起止时间 |
| **无信用体系** | 爽约行为依赖人工记录，缺乏自动化黑名单和信用扣分 |
| **无实时占用状态** | 预约后无法直观看到功能房占用时间线 |
| **纸质流程繁琐** | 多类功能房需打印申请表、找辅导员签字、交物业前台 |
| **缺少消息推送** | 审核结果无法主动通知用户 |
| **阅览室登记独立** | 与整体预约体系割裂 |
| **二期1幢未纳入** | 现有系统未覆盖二期1幢的功能房 |

### 1.3 项目目标

建设一套**自主可控、功能全面、体验流畅**的敬一书院功能房预约管理系统：
- **宿生端（微信小程序）**：统一入口，一码通全覆盖 BCD座 + 二期1幢 全部功能房的预约
- **导生会管理端（Web后台 + 小程序管理版）**：统一审核、实时监控、数据分析、违规管理
- 技术栈：**微信小程序原生 + Node.js Express + MySQL + Redis + 微信订阅消息**

### 4.2 自习室预约 —— 「时间线自由选择」（⭐ 核心亮点）

这是系统最核心的交互模块，推广到所有需预约的功能房。

#### 4.2.1 第一步：选择自习室
- 列表展示 5 间自习室，含：
  - 房号 + 座位数
  - 拥挤度指示（颜色进度条）
  - 实时可预约数
- 点击进入目标自习室

#### 4.2.2 第二步：选择日期
- 横向滑动日历组件
- 可预约范围：今天 ~ 今天+3天（可配置）
- 超出范围的日期置灰
- 当天未到预约开放时间（如8:00前）也置灰

#### 4.2.3 第三步：座位 + 时间线可视化（核心创新）

- 已选范围高亮显示，显示时长和"确认预约"按钮
- 支持横向滑动查看全天24小时

#### 4.2.4 第四步：确认预约信息
- 所选自习室 + 座位号 + 日期 + 时间段
- 自动填充：学号、姓名、性别、年级专业

#### 4.2.5 第五步：预约成功

#### 5.4.1 信用分体系（可配置）

| 行为 | 分数变动 |
|------|----------|
| 初始信用分 | +100 |
| 爽约1次 | **-20分** |
| 违规使用（损坏设备、大声喧哗被投诉等） | **-10~-30分** |
| 违规张贴海报（逾期未清理等） | **-15分** |
| 良好使用记录：每10次无违规 | **+5分**（上限120分） |
| 主动反馈问题/建议被采纳 | **+3分** |

| 信用分区间 | 状态 |
|------------|------|
| 80-120 | 正常使用 |
| 60-79 | **警告**（可预约，但预约上限减半） |
| 30-59 | **限制**（暂停预约资格7天） |
