## 一、项目背景与现有问题分析

### 1.1 现状

敬一书院目前通过「草料二维码」第三方平台来实现功能房预约管理。宿生扫描各功能房门上的二维码进入草料二维码小程序，填写表单提交预约，导生会后台审核。

### 1.2 现有痛点

| 问题 | 说明 |
|------|------|
| **依赖第三方平台** | 草料二维码非自主可控，数据安全存在隐患，后续可能收费 |
| **体验割裂** | 每种功能房需扫不同二维码，表单填写繁琐，重复输入个人信息 |
| **缺乏可视化管理** | 无统一后台看板，审核效率低，数据分析能力弱 |
| **时间粒度粗糙** | 仅支持固定时段（如上午/下午/晚上），无法灵活选择起止时间 |
| **无信用体系** | 爽约行为记录依赖于人工，缺乏自动化的黑名单和信用扣分机制 |
| **无实时占用状态** | 预约后无法直观看到功能房占用时间线（绿色→红色），用户需反复询问 |
| **手动导出打印** | 舞蹈室、多功能厅需导出打印申请表、找辅导员签字，流程繁琐 |
| **缺少消息推送** | 预约审核结果无法主动通知用户，需用户自行查看 |
| **阅览室登记独立** | 阅览室为独立扫码登记，与整体预约体系割裂 |

### 1.3 项目目标

建设一套**自主可控、功能全面、体验流畅**的敬一书院功能房预约管理系统，包含：

- **宿生端（微信小程序）**：统一入口，一码通扫，覆盖所有功能房的预约、签到、取消、历史查看
- **导生会管理端（Web后台 + 小程序管理版）**：统一审核、实时监控、数据分析、违规管理
- 技术栈：**微信小程序原生 + Node.js Express + MySQL + Redis + 微信模板消息/订阅消息**

## 四、宿生端（微信小程序）功能设计

### 4.1 首页 —— 「功能房总览」

#### 4.1.1 顶部区域
- 书院Logo + "敬一书院功能房预约"
- 用户头像 + 姓名 + 当前信用分
- 实时时间显示

#### 4.1.2 功能房分类卡片（宫格或列表）

以卡片形式展示每种功能房类型，每张卡片包含：
- 功能房图标 + 名称
- 当前空闲/占用状态（直观标识）
- 点击进入该类型功能房的预约详情页

分类顺序：
1. 自习室（含座位预约特有的时间线界面）
2. 研讨室
3. 影音室
4. 科技创新备赛间
5. 舞蹈室
6. 多功能厅
7. 阅览室（扫码登记入口）
8. 海报栏（申请入口）

#### 4.1.3 底部导航栏
- 首页（功能房列表）
- 我的预约
- 消息通知
- 我的（个人信息/设置）

### 4.2 自习室预约 —— 「时间线自由选择」（核心亮点）

这是整个系统交互最复杂的模块：

#### 4.2.1 第一步：选择自习室房间
- 列表展示 C110 / D510 / D418
- 用颜色条展示每间自习室的当前拥挤度（如绿色=空闲多，黄色=适中，红色=紧张）
- 点击进入具体自习室的座位预约

#### 4.2.2 第二步：选择日期
- 日历组件，可选择"今天"和"明天"（仅允许提前1天）
- 不可选择的日期置灰

#### 4.2.3 第三步：座位+时间线可视化（核心交互）

这是最重要的UI创新点 —— **每间自习室的每个座位都以一条时间线展示**：

```
    座位号    08:00  09:00  10:00  11:00  12:00  13:00  14:00  15:00 ...
    ─────────────────────────────────────────────────────────────────
    座位01    [████████████████] [░░░░░░░░░░░░] [██████████████████]
    座位02    [░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░]
    座位03    [░░░░░░] [████████████████████████████████████████████]
    座位04    [░░░░░░░░░░░░░░░░░░░] [██████████████████████████████]
    ...

    ░░ = 绿色 = 空闲可预约
    ██ = 红色 = 已被占用
```

交互方式：
- 用户点击一个座位行上的"绿色空闲区域"，弹出时间选择器
- 可以用**滑块拖拽**选择起始时间和结束时间（精确到小时）
- 例如：从 14:00 拖到 18:00，即为预约 14:00-18:00（共4小时）
- 系统实时校验：不超过该自习室的单次预约上限（C110/D510=4h，D418=2h）
- 选择时间段后，显示"确认预约"按钮

#### 4.2.4 第四步：填写预约信息
- 学号（自动从微信绑定信息获取）
- 姓名（自动获取）
- 性别
- 年级专业
- 手机号
- 一卡通号（新增字段）
- 确认预约

#### 4.2.5 第五步：预约成功
- 显示预约详情卡片（含座位号、时间段、日期）
- 生成「预约凭证码」—— 供到自习室门口扫码签到用
- 自动发送微信订阅消息提醒

### 4.3 研讨室/影音室/备赛间预约

#### 4.3.1 选择房间 → 选择日期 → 选择时间段
- 以日历+时间段表格的形式展示
- 时间段以半小时/一小时为单位，已预约的格子显示为红色
- 用户点击选择起止时间

#### 4.3.2 填写预约信息
- 学号、姓名、性别、年级专业、手机号、一卡通号、校内邮箱
- 所属组织或单位
- 参与人数
- 使用用途（研讨室特别增加用途分类选择）
- 是否需要使用多媒体设备（研讨室）
- 是否需要使用自带电器（研讨室，需说明电器名称/功率/原因）

### 4.4 舞蹈室/多功能厅预约

- 流程同上，但增加了**需要辅导员线下签字审批**的流程状态
- 线上提交后，系统生成PDF申请表，用户需下载打印后交至书院办公室
- 或者：系统支持**电子签名/审批**，辅导员在线签字后即可生效（需后续沟通实现）

建议实现方案：
- 用户小程序提交后 → 导生会管理员初审核 → 系统自动推送通知给对应辅导员 → 辅导员在后台电子审批签字 → 无需打印纸质

### 4.5 阅览室登记

- 无需预约，用户到达阅览室后扫描门口二维码
- 进入「阅览室登记」页面，自动填写个人信息
- 点击「登记进入」即完成
- 离开时再次扫码点击「登记离开」
- 登记信息仅包含：学号、姓名、进入时间、离开时间

### 4.6 海报栏申请

- 填写申请表单：
  - 申请单位、联系人、联系方式、邮箱
  - 是否为院级/校级组织
  - 海报数量、张贴地点
  - 海报主题
  - 申请时段（起止日期，最多7天，特殊活动可申请14天）
  - 海报预览图上传
- 提交后等待审核

### 4.7 「我的预约」页面

| 标签页 | 内容 |
|--------|------|
| 待审核 | 已提交等待审批的预约 |
| 已通过 | 审批通过、待使用/使用中的预约 |
| 已使用 | 历史已完成的使用记录 |
| 已取消 | 主动取消或被驳回的预约 |
| 已爽约 | 到时间未签到被标记为爽约的记录 |

每个预约记录卡片展示：
- 功能房名称+房号
- 预约日期 + 时间段
- 当前状态标签（彩色标签）
- 操作按钮：取消预约（开始前3小时）、签到、查看凭证码

### 4.8 「消息通知」页面

- 审核结果通知（通过/驳回+原因）
- 预约即将开始提醒（开始前30分钟）
- 预约即将结束提醒（结束前15分钟）
- 爽约警告通知
- 信用分变动通知
- 系统公告

### 4.9 「我的」页面

- 个人信息展示（头像、姓名、学号、信用分）
- 个人信息修改（手机号、邮箱等）
- 信用分详细（扣分/加分记录）
- 帮助与反馈
- 功能房管理制度（各类管理规定在线阅读）
- 设置（订阅消息管理、关于系统）

### 5.2 预约管理

#### 5.2.1 预约审核
- 待审核列表（按提交时间排序）
- 每条预约展示：申请人信息、功能房、时间、用途
- **一键通过/驳回** + 填写审核备注
- 支持批量审核
- 自动检测冲突（同一时间段同一功能房是否已被其他人预约）

#### 5.2.2 预约记录管理
- 全部预约记录查询（多条件筛选）
- 按功能房、日期、状态、申请人筛选
- 支持导出Excel

#### 5.2.3 预约规则配置
- 配置每种功能房的开放时间
- 配置单次预约时长上限

### 6.2 核心接口详细设计 —— 时间线数据

这是整个系统最关键的数据接口，以自习室为例：

**GET `/api/v1/room/:id/timeline?date=2026-05-19`**

返回数据格式：

```json
{
  "code": 200,
  "data": {
    "roomId": "C110",
    "roomName": "C110自习室",
    "date": "2026-05-19",
    "openTime": "00:00",
    "closeTime": "23:59",
    "maxHours": 4,
    "seats": [
      {
        "seatId": "C110-01",
        "seatNo": "01",
        "timeline": [
          { "hour": 0, "status": "unavailable" },
          { "hour": 1, "status": "unavailable" },
          ...
          { "hour": 8, "status": "available" },
          { "hour": 9, "status": "available" },
          { "hour": 10, "status": "occupied", "reservationId": "xxx", "endTime": "14:00" },
          { "hour": 11, "status": "occupied", "reservationId": "xxx", "endTime": "14:00" },
          { "hour": 12, "status": "occupied", "reservationId": "xxx", "endTime": "14:00" },
```

- `available`：绿色，可预约

| 场景 | 推送时机 | 模板内容 |
|------|----------|----------|
| 预约审核结果 | 审核通过/驳回时 | 「您的{功能房}预约已{通过/驳回}」 |
| 预约开始提醒 | 预约开始前30分钟 | 「您的{功能房}预约将于30分钟后开始」→ 附带签到入口 |
| 预约即将结束 | 结束前15分钟 | 「您的{功能房}使用时间将于15分钟后结束，请及时清理」 |
| 爽约警告 | 被标记爽约后 | 「您有1次爽约记录，请遵守预约规则」 |
| 信用分变动 | 扣分/加分时 | 「您的信用分变更为{新分数}，原因：{原因}」 |
| 系统公告 | 新公告发布时 | 公告标题+摘要 |

### 8.2 小程序内通知

所有通知同时在小程序「消息」页面展示，支持：
- 未读红点
- 分类筛选
- 已读/未读状态

### 8.3 Web后台通知

管理端使用WebSocket实时推送：
- 新预约提交提醒
- 预约即将到期待审核
- 违规预警

## 九、安全与权限设计

### 9.1 认证机制

- **小程序端**：微信openid + JWT Token，首次登录需绑定学号+姓名
- **管理端**：账号密码 + JWT Token，支持双因子（可选）
- Token有效期：access_token 2h + refresh_token 7d
- 所有API请求需携带 `Authorization: Bearer <token>`

### 9.2 权限矩阵

| 操作 | 宿生 | 导生会管理员 | 辅导员 | 超级管理员 |
|------|:--:|:--------:|:---:|:-------:|
| 预约功能房 | ✓ | ✓ | ✓ | ✓ |
| 取消自己的预约 | ✓ | ✓ | ✓ | ✓ |
| 查看自己的预约 | ✓ | ✓ | ✓ | ✓ |
| 审核预约 | ✗ | ✓ | ✗ | ✓ |
| 多功能厅审批 | ✗ | ✗ | ✓ | ✓ |
| 查看所有预约 | ✗ | ✓ | 部分 | ✓ |
| 管理违规 | ✗ | ✓ | ✗ | ✓ |
| 导出报表 | ✗ | ✓ | ✓ | ✓ |
| 配置功能房规则 | ✗ | ✗ | ✗ | ✓ |
| 管理管理员 | ✗ | ✗ | ✗ | ✓ |

### 9.3 接口安全

- 参数校验（express-validator）
- SQL注入防护（参数化查询）
- XSS防护（输出编码）
- 接口频率限制（express-rate-limit）
- 预约冲突检测（数据库行锁 + Redis分布式锁）
- 敏感操作日志记录

## 十、UI/UX 设计要点

### 10.1 视觉风格

- **主色调**：书院蓝（#0066CC → 接近现有草料二维码的蓝色风格）
- **辅助色**：
  - 绿色 #52C41A（空闲/成功）
  - 红色 #FF4D4F（占用/警告/违规）
  - 橙色 #FA8C16（即将到期/提醒）
  - 灰色 #D9D9D9（不可用/禁用）
- **设计风格**：清爽简洁的校园风格，避免过于花哨

### 10.2 核心交互原则

1. **一码通行**：所有功能房统一入口，一个二维码覆盖全部
2. **最少点击**：从首页到完成预约不超过5步
3. **状态可见**：时间线可视化是最核心的设计语言
4. **及时反馈**：每个操作有明确的loading→成功/失败反馈
5. **容错设计**：关键操作有二次确认弹窗

## 附录：与旧系统（草料二维码）对比

| 维度 | 草料二维码旧系统 | 新系统 |
|------|:---------:|:-----:|
| 入口 | 多个二维码，分散 | 一个统一二维码 |

| 状态可视化 | 无 | 绿色→红色实时时间线 |

| 辅导员审批 | 线下纸质签 | 线上电子审批 |
| 消息推送 | 无 | 微信订阅消息 |
| 信用体系 | 无自动化 | 自动扣分+黑名单 |
| 数据分析 | 无 | 多维统计报表 |
| 阅览室 | 独立扫码登记 | 统一体系 |
| 海报栏 | 独立系统 | 统一审核+位置管理 |
| 数据安全 | 第三方平台 | 自有服务器 |
